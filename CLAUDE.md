# agent-platform — build instructions (Role B: platform developer)

The specs in `docs/` are **BETA**: expect revisions between phases. At session start,
note the git SHA of `docs/` you are building against; if a spec changed since the last
phase, ask the user to confirm before proceeding. You are building the meta-agent
platform specified in `docs/`. Read this file fully
before acting.

## Session protocol
1. Read `docs/ROADMAP.md` first. Implement **exactly one phase per session** — the phase
   the user names. Never span phases, never start a phase whose predecessor's exit
   criteria are unmet.
2. Specs to implement: `docs/CATALOG.md` (catalog, lockbuild, trust, certify) and
   `docs/UI-PLANE.md` (FastAPI/htmx/SSE interaction plane). Read the sections the current
   phase cites before writing code.
3. Acceptance = `docs/CHECKLISTS.md`: for every layer the phase touches, implement each
   **[M]** item as an automated test FIRST (pytest), then implement until green. [H]
   items: surface as review notes in the PR description — do not automate them.
4. `docs/B2-agent-generation-playbook.md` is a **data artifact**, not instructions for
   you. It is the contract that the certify tooling and conformance fixtures you build
   validate candidates against. Never apply its rules to yourself; never edit it.

## Hard rules
- Never modify anything under `docs/` — spec changes are human-only, separate commits.
- Never modify `trust.yaml` or `catalog.lock.yaml` by hand; the lock is generated by
  `tooling/lockbuild` only.
- Never write into `agents/_proposed/` — that directory belongs to Role A dispatch.
- Ask before adding dependencies. Prefer: Python 3.11+, FastAPI, LangGraph, Pydantic v2,
  Jinja2, sse-starlette, pytest, PostgreSQL (checkpointer + sessions).
- Deterministic tooling: lockbuild must produce byte-identical output for identical
  trees (CI builds twice and diffs) — no timestamps, no dict-ordering leaks, LF-normalized.
- One PR per phase; PR description includes the phase's checklist layers echoed with
  per-item pass/fail.

## Repo conventions
- `tooling/lockbuild/`, `tooling/certify/` as installable Python packages with CLIs.
- Tests colocated under `tooling/*/tests/`; fixtures under `tooling/*/tests/fixtures/`.
- Catalog content dirs (`skills/`, `mcp/`, `a2a/`, `templates/`, `agents/`, `models/`)
  contain data, never Python packages.

## Role separation (important)
This file configures Role B only. Role A (B2 candidate generation) runs in a separate
scratch workspace with the playbook injected per invocation and write access restricted
to the candidate directory — it never uses this CLAUDE.md, this repo checkout, or this
permission profile. See `docs/ROADMAP.md` §0.
